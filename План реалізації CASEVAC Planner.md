# План реалізації веб-додатку CASEVAC Planner

**Версія:** 0.1  
**Дата:** 26.10.2026  
**Основа:** [Технічне завдання CASEVAC](ТЗ%20веб-додаток%20CASEVAC%20для%20медичного%20відділу.md)

## 1. Мета

Створити україномовний SPA для медичного відділу організації з гуманітарного розмінування. Застосунок дозволить вести картки медичних закладів, створювати й супроводжувати маршрути CASEVAC на карті, а для кожного маршруту формувати картографічний JPG і План реагування у Word.

Застосунок працює в браузері, автентифікує користувача через ArcGIS Enterprise Portal та читає/редагує дані через ArcGIS Feature Services від імені користувача. Власний сервер і офлайн-режим не плануються.

## 2. Структура застосунку

### 2.1 «Медичні заклади»

Сторінка для керування закладами:

- список закладів із пошуком і переглядом основної інформації;
- створення нового закладу з вибором місця на карті;
- перегляд і редагування атрибутивних даних у формі, згрупованій за розділами;
- списки значень для полів із доменами ArcGIS-сервісу;
- перевірка обов'язкових полів перед збереженням;
- фіксація `last_visit_date` і `visited_by` під час оновлення картки;
- блокування видалення закладу, якщо на нього посилаються маршрути.

Повний перелік полів, типів і груп форми буде реалізовано після отримання Додатка А до ТЗ.

### 2.2 «Маршрути CASEVAC»

Сторінка поєднує карту й роботу зі списком маршрутів:

- завантаження WebMap і відображення мінних полів, маршрутів, медичних закладів та початкових точок евакуації;
- перемикання видимості шарів, легенда, пошук поля/закладу та синхронні фільтри карти й списку;
- перегляд маршруту та пов'язаних поля, закладу й початкової точки;
- створення маршруту вручну, редагування геометрії та атрибутів, деактивація й повторна активація, копіювання як чернетки;
- автоматичне створення та супровід початкової точки евакуації;
- дії для кожного маршруту: **«Створити карту»** та **«Експортувати План реагування»**.

Автоматичне прокладання маршруту буде окремим наступним етапом після доступності й перевірки routing utility service у Portal. Ручне прокладання не залежить від цієї інтеграції.

## 3. Технологічна основа

- TypeScript і Vite для клієнтського застосунку;
- ArcGIS Maps SDK for JavaScript сумісної з ArcGIS Enterprise 11.5 версії;
- Calcite Design System, українська мова інтерфейсу;
- OAuth 2.0 PKCE через `OAuthInfo` та `IdentityManager`;
- ArcGIS REST Feature Services для читання й редагування даних;
- бібліотека генерації DOCX буде остаточно обрана під час прототипу роботи з наданим шаблоном;
- GitHub Actions і GitHub Pages для публікації SPA.

Конфігурація адрес Portal, WebMap і шарів зберігається окремо від логіки. Токени, паролі, Client Secret та дані організації не додаються до репозиторію.

## 5. Узгоджені правила реалізації

- Сторінок дві: «Медичні заклади» та «Маршрути CASEVAC». Окрему загальну сторінку карти не створювати; карта є частиною сторінки маршрутів.
- Початкова точка евакуації збігається з першою вершиною маршруту та створюється/оновлюється автоматично.
- Канонічний напрямок лінії: **мінне поле → лікарня**. Якщо користувач креслить навпаки, застосунок нормалізує напрямок за близькістю кінців до поля й закладу; неоднозначний випадок потребує перевірки до збереження.
- Для одного мінного поля можуть існувати кілька актуальних основних маршрутів. Обмеження «лише один актуальний основний» з початкової редакції ТЗ не застосовувати.
- Список медиків завантажується з домену поля сервісу; поточного користувача автоматично не підставляти.
- Формат координат — десяткові градуси. Початковий поріг валідації відстані кінців маршруту — 500 м, винесений у конфігурацію.
- Автоматична маршрутизація не є передумовою для першого ручного робочого циклу.

## 6. Залежності та ризики

- Для сторінки закладів необхідний Додаток А з полями, доменами та правилами обов'язковості.
- Для експорту необхідні Додаток Б (шаблон Word і таблиця відповідності полів) та Додаток В (макет карти).
- Запис у Start evac point неможливий, доки не буде доступний редагований FeatureServer.
- Записи маршруту й початкової точки можуть виконуватись у різні сервіси й не бути атомарними; потрібне явне відновлення/відкат при частковому збої.
- Автоматична маршрутизація залежить від utility service, авторизації та можливої конфігурації кредитів ArcGIS Online.
- Публічний GitHub Pages не повинен містити шаблон Word, токени чи приватні дані.
- A3 JPG 300 dpi потребує раннього тесту обмежень пам'яті браузера та завантаження тайлів.

## 7. Передумови для першого запуску з реальними даними

1. Підтвердити зовнішню доступність `https://gis.htgoims.org/portal` і налаштувати точний OAuth Redirect URI для localhost та GitHub Pages.
2. Дозволити потрібні origin у CORS і Trusted Servers на Portal/ArcGIS Server.
3. Підтвердити поля та домени сервісів, увімкнути Editor Tracking і надати редагований FeatureServer для шару початкових точок.
4. Надати Додатки А–В.
5. Погодити адресу репозиторію та GitHub Pages після його створення.

## 8. Межі першого інкременту

Перший інкремент реалізації — каркас застосунку з навігацією, українським адаптивним інтерфейсом і двома робочими сторінками-заготовками. Дані, редагування сервісів, авторизація та експорт підключатимуться наступними інкрементами після перевірки конфігурації Portal і доступності схем сервісів.
