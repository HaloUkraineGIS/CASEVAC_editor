# CASEVAC Planner

Веб-додаток медичного відділу для ведення карток медичних закладів, маршрутів евакуації CASEVAC та формування картографічних матеріалів і Планів реагування.

Односторінковий клієнтський застосунок (React + TypeScript + Vite) без власного серверу. Робота з даними — через ArcGIS REST API від імені користувача ArcGIS Enterprise Portal.

## Швидкий старт

```bash
npm install
npm run dev
```

Застосунок відкриється на `http://localhost:5173/CASEVAC_editor/` (шлях заданий `base` у `vite.config.ts`; корінь `http://localhost:5173/` перенаправляє туди). Типово він працює в **демо-режимі**: локальні демонстраційні дані, вхід не потрібен.

## Режими роботи

| Режим | `VITE_AUTH_MODE` | Дані | Вхід |
| --- | --- | --- | --- |
| Демо | `demo` (типово) | `src/data/demoData.ts`, зміни лише в пам'яті сторінки | не потрібен |
| Portal | `portal` | шари ArcGIS через REST від імені користувача | OAuth 2.0 PKCE |

Приклад конфігурації — `.env.example`. Скопіюйте його у `.env.local`:

```bash
VITE_AUTH_MODE=portal
VITE_PORTAL_URL=https://gis.htgoims.org/portal
VITE_OAUTH_CLIENT_ID=UkLjSBHNNooE1jnb
VITE_OAUTH_REDIRECT_URI=http://localhost:5173/CASEVAC_editor/
VITE_WEBMAP_ID=f5c528f766ec467c9d7388787bc58698
```

Усі адреси, ID веб-карти, назви полів, пороги валідації та строки «потрібен візит» зібрані в `src/config/appConfig.ts`.

## Налаштування Portal (передумова режиму `portal`)

1. Додати Redirect URI у налаштуваннях OAuth-застосунку `UkLjSBHNNooE1jnb`
   (значення має точно збігатися з `VITE_OAUTH_REDIRECT_URI`, включно зі слешем):
   - `http://localhost:5173/CASEVAC_editor/`
   - `https://<org>.github.io/<repo>/`
2. Дозволити ці origin-адреси в CORS на ArcGIS Server/Portal.
3. Додати `gis-services.htgoims.org` і `gis.htgoims.org` у Trusted Servers Portal.
4. Переконатися, що шари початкових точок доступні як FeatureServer (зараз MapServer — запис неможливий).

### Якщо вхід не працює

- **Сторінка Portal відкривається як сирий HTML, у консолі `SyntaxError: JSON.parse: unexpected character…`.**
  Причина — параметр `f=json` в адресі `oauth2/authorize`: Portal віддає сторінку входу з
  `Content-Type: application/json`, і браузер показує її текстом. У `buildAuthorizeUrl`
  (`src/auth/pkce.ts`) цей параметр передавати не можна.
- **`Invalid redirect_uri` або після входу повертає на порожню сторінку.**
  `VITE_OAUTH_REDIRECT_URI` має точно (включно зі слешем і шляхом `base`) збігатися з
  Redirect URI, зареєстрованим у Portal.
- **`Portal повернув HTML-сторінку замість JSON`.** Сесія Portal завершилася або REST API
  перекритий проксі; увійдіть повторно й перевірте CORS/Trusted Servers.

## Структура

```
src/
  config/appConfig.ts     налаштування Portal, шарів, полів, порогів
  types.ts                доменні типи
  auth/                   OAuth PKCE, запити до Portal, стан входу
  data/                   джерела даних: демо та ArcGIS REST, React-контекст
  components/             оболонка, навігація, модальні вікна, сповіщення
  pages/                  чотири сторінки застосунку
  lib/                    форматування дат, координат, схема картки закладу
  styles.css              стилі інтерфейсу
```

## Що вже працює

- чотири сторінки: маршрути, заклади, план на область, план CDS (EOD);
- демо-дані, пошук і фільтри, перегляд зв'язків маршрут ↔ заклад;
- створення чернеток маршруту та закладів у демо-режимі;
- позначення закладів, які давно не відвідували (поріг у конфігурації);
- OAuth PKCE з Portal, відновлення сесії, вихід;
- модальне вікно входу (SSO): сторінка Portal відкривається в поточній вкладці без спливаючих вікон, після авторизації код повертається в застосунок автоматично;
- читання чотирьох шарів через ArcGIS REST (потребує токена й налаштованого Portal);
- картка закладу: перегляд і редагування всіх атрибутів шару, форма генерується з метаданих сервісу (поля, alias, типи, домени, обов'язковість) і групується за розділами — загальне, відділення, paraclinical служби, візит/оновлення даних (FR-9). Поля координат (широта/довгота) не показуються користувачу; x/y розраховуються автоматично з точки, обраної на карті;
- для полів без домену або з технічними кодами (`yes` / `no` / `possible`) діють локальні українські довідники; для реального шару підписи полів також українізовані;
- створення закладу з вибором точки на карті, перевірка обов'язкових полів і доменів (FR-10). Кнопка редагування у рядку списку прибрана — редагування/видалення доступні в картці «Переглянути»;
- під час кожного збереження оновлюються дата візиту (типово сьогодні) і виконавець (FR-11). У реальному шарі це поля `status_date` і `created_by_medic`; підтримуються також `last_visit_date` / `visited_by`;
- дата останнього візиту в списку та позначка «потрібен візит» після N місяців (FR-12);
- на сторінці закладів додано панель карти з усіма лікарнями (OpenStreetMap): вибір лікарні кліком на карті, підсвічування вибраного закладу, автопідбір масштабу та прокрутка списку до вибраного закладу;
- видалення закладу через `applyEdits`, заборонене за наявності пов'язаних маршрутів (FR-13).

## Перевірка на реальному шарі

26.10.2026 застосунок перевірено на FeatureServer `ukr_CASEVAC_routes_medical_facilities` з тимчасовим токеном, виданим для `gis-services.htgoims.org`:

- прочитано **127 медичних закладів** і **996 маршрутів**; `capabilities` шару закладів — `Query,Create,Update,Delete,Uploads,Editing,Extract,ChangeTracking`;
- реальна схема закладу містить `name_ukr`, `full_name_ukr`, `name_eng`, `full_name_eng`, `region`, `address`, `phone`, `contact_ukr`, `contact_eng`, `type_of_hospital`, `x`, `y`, 21 поле можливостей, `created_by_medic`, `is_active`, `status_date`; окремого поля «Відділення» немає, тому список показує стислий перелік наявних можливостей;
- виправлено завантаження: у шару мінних полів `objectIdField` у метаданих дорівнює `null` (фактично `task_id`), через що запит з `orderByFields=objectid` повертав `400 Invalid or missing input parameters` і блокував всю сторінку. Тепер OID/GID визначаються за типами полів, а сортування додається лише за наявності поля;
- карта вибору точки використовує відкриту підкладку OpenStreetMap і не залежить від доступності веб-карти Portal. Це важливо, бо токен, виданий для `gis-services.htgoims.org`, веб-карта на `gis.htgoims.org` не приймає (`498 Invalid Token`);
- реальні операції запису (`applyEdits`) на продакшн-шарі ще не виконувались — потрібне окреме підтвердження відповідальної особи.

## Що ще не реалізовано

- посторінкове завантаження великих шарів і кешування (зараз — повне читання при оновленні);
- створення й редагування геометрії маршрутів у ArcGIS (етапи 3–5);
- автоматична маршрутизація (етап 8);
- експорт JPG і DOCX (етапи 5–7).

Деталі та послідовність — у [журналі розробки](Журнал%20розробки%20CASEVAC%20Planner.md).

## Безпека

- у репозиторії немає токенів, паролів і Client Secret;
- токен доступу зберігається лише в `sessionStorage` поточної вкладки;
- Client ID є публічним ідентифікатором OAuth-застосунку;
- шаблон Word не публікується в репозиторії, а завантажується з Portal після входу (FR-33).
